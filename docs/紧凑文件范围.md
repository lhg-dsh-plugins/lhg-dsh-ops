# 紧凑文件范围

English: [Compact Native file ranges](native-ranges.md).

`ops_read_files` 完整返回所请求的范围时，每个文件仅显示一个路径标题、精确的行号正文，以及一条版本/续读提示。只有所有文件具有完全相同的绝对父目录时，才共享一条 JSON 引号包围的 `Base`；各文件名同样使用 JSON 引号，并相对于该目录解析。父目录不同则保留各自的绝对路径。

```text
[Base: "/workspace/src"]
=== FILE: "server.ts" (Lines 1-2 of 80) ===
1|import { createServer } from 'http';
2|const port = 8080;
[revision=cfd1bc81432fd6b88748b827f46bb4242db17cf8655cf4ea90f3ba0e62065355; more lines; nextOffset=3]
```

`N|` 后紧跟原始行内容，包含原有缩进。正文使用可逆 JSON 转义：反斜杠写成双反斜杠，控制字符及 Unicode 换行分隔符被转义，引号保持原样。例如真实制表符显示为 `\t`，而反斜杠加字母 t 的两个源字符显示为 `\\t`。紧凑范围和普通行号正文共用此编码，防止伪造额外行号或文件标题；LF/CRLF 物理行规则与 worker 保持一致。

`more lines` 表示文件尚未读到末尾，按 `nextOffset` 继续；`end of file; complete=true` 表示本范围已经到达文件末尾。汇总的 `requested ranges returned` 仅证明所请求的范围正文全部返回，不代表读取了所有完整文件。完整版本散列、总行数和每个文件的续读位置继续保留；字节大小及重复计数仍在规范数据和 PTC 返回值中。逐文件版本回执省去重复的 `Notice: ` 前缀与末尾句点；汇总 `Notice` 以及版本、续读和完整性事实均保留。

发生物理截断、缺失文件、覆盖事实异常、引用存储或其他不确定情况时，继续使用诊断输出并保留明确恢复提示。最终显示预算截断不会保留成功汇总，而会要求用更小上限重新读取原范围。上下文去重同时识别 `N|` 与现有单文件 `N | ` 格式；只有当前供应商上下文中存在完全相同的旧正文证据，才能返回未变化引用。
